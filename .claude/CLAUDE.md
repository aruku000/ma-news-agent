# M&Aニュース音声エージェント（オープンリスト AB5「EDINET, TDnet, 日経」、doc id t1020-089）

## 目的・概要
- 毎朝、M&A関連の開示を集めて要約し、読み上げた MP3 を Googleドライブに置く。山田さんは通勤の自転車でスマホのドライブアプリから聞く
- 一般ニュースは対象外。集めるのは3つ
  - ① ロングリストの上場企業の、資本政策に直接・間接に効くイベント（大量保有・公開買付・臨時報告書・資本業務提携・自己株・MBO など）
  - ② 国内の主要ディール。網羅は不要で、規模が大きいものか SaaS・HRテックに近いものだけ
  - ③ ①以外の上場企業のうち、セキュリティ、DXコンサル・SES、SMBの資金繰り・決済、リアル産業DX（建設・製造の設計、不動産）に関係する会社の開示（2026-11-02 追加）。AB1 の要件書ほど厳密に定義しない。語は `collect.py` の THEMES、当否の見方は RUNBOOK
    - TDnet のタイトルはほとんど事業を語らない（10営業日3,045件でテーマの語に当たるのは数件）。だから資本イベントの開示は本文の冒頭6,000字の語でふるい、語で落ちた分も `screened_out` に残して Claude が社名で見直す
    - EDINET は③に使わない（大量保有は一覧から発行会社の事業が分からず、臨時報告書は同じ内容が TDnet に出るため）
- MVP は EDINET と TDnet。日経は第2段階（契約の有無が未確認）
- 原典：Obsidian `Vault_R/Memo/Archive/20260721_news.md`。メモリ `project_ma_news_agent.md`

## 処理の流れ
| 段階 | 誰が | 何を | 出力 |
|---|---|---|---|
| 1 | `collect.py` | TDnet・EDINET を読み、語で対象を選び、PDF本文をテキストにする | `runs/<日付>/items.json`、`txt/` |
| 2 | Claude（RUNBOOK） | 本文を読み、規模・SaaS/HR で②を絞り、要約と読み上げ原稿を書く | `ma_news_<日付>.md`、`script.txt` |
| 3 | `tts.py` | 原稿を MP3 にする | `ma_news_<日付>.mp3` |
| 4 | `upload_drive.py` | Drive のフォルダへ置く。あわせて `ma_news_latest.mp3`／`.md` を同じIDのまま差し替える（携帯のホーム画面用、2026-11-04〜。README の案A） | `drive.json` にフォルダIDと latest のID |

毎日の手順の正は `RUNBOOK.md`。方針と比較は `README.md`。クラウドで動かすときの違い（鍵・引き継ぎ・ウォッチ先がコードだけ）は `CLOUD.md`。

## Claude Code への指示・注意
- EDINET の本文は type=1（ZIP）の PublicDoc の HTML から取る。type=2 の PDF は pdftotext で文字が取れず、空のファイルになる（2026-11-02 確認）
- ロングリストは社外秘。**音声と要約に「ロングリスト」「優先度」「A/B/C」「投資テーマ」「ターゲット」を入れない**（読み上げの文章は外部のTTSに送るため。言うのは会社名と開示の事実だけ。③の見出しは「そのほかの開示」）
- 共有設定を付けない。Drive のフォルダは持ち主だけが見られる状態を保つ
- 数字・事実は開示本文から。推定は「推定」と言う。読めなかったものはタイトルだけで「本文未確認」と言う
- 定期実行の登録・有料APIの契約は山田さんのOKの後
- 取得は1秒間隔。TDnet・EDINET への並列アクセスはしない
- 同じやり方で2回失敗したら、理由を `logs/<日付>.md` に書いて止まる
- 返答・ログは日本語
